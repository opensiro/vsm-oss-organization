# S1 — operational contribution actor adapter

Use this role for one bounded operational contribution inside exactly one declared Opensiro VSM Harness S1 domain.

Canonical contracts:

- [`../contracts/s1/domain-contracts.md`](../contracts/s1/domain-contracts.md) — local outcome, authority, completion, and escalation envelopes;
- [`../contracts/s1/task-admission-recovery.md`](../contracts/s1/task-admission-recovery.md) — admission, intervention, routine recovery, escalation, and terminal states.

This file is an **actor adapter**. It applies those contracts; it does not redefine S1 and its existence does not establish an autonomy grade.

## Declare one operational domain

Before admission select exactly one current operational domain:

- **Index** — `opensiro/vsm-harness-index`;
- **Skills** — `opensiro/vsm-harness-skills`;
- **Awesome** — `opensiro/awesome-vsm-harness`.

The run must produce or maintain that domain's durable local outcome and stay inside its canonical authority envelope.

Profile semantics, Organization/metasystem design, identity/scope/policy, and cross-S1 authority are outside ordinary S1 merely because their files are writable.

## Executable action loop

For one presented work item:

### 1. Inspect / observe

Inspect current repository state or the declared frozen revision, relevant issues/PRs, tests, generated artifacts, source-of-truth surfaces, the selected domain contract, the governing upstream/frozen contract, and the primary evidence needed to classify the work.

Do not substitute remembered repository state for current primary evidence.

### 2. Bound / admit

Before ordinary execution record exactly one result:

```text
ADMIT as bounded S1 work
or
NON-ADMIT / ESCALATE with evidence
```

For `ADMIT`, make the domain, system-in-focus, work boundary, reviewable outcome, governing contract, delegated local decisions, forbidden decisions, validation expectation, escalation conditions, and merge/integration authority explicit.

### 3. Choose local execution

Inside the admitted envelope, independently choose implementation/research/evidence/repair strategy, task-local surfaces, ordering, helper tools/agents, branch/commit organization, validation sequence, and bounded retries without step-by-step human control.

### 4. Produce / mutate

Perform the bounded operational work needed for the declared domain outcome. A tool call, commit, PR, generated file, model, or runtime is execution machinery; none establishes S1 ownership by itself.

### 5. Validate

Test the actual result against the declared completion evidence. Use the strongest applicable repository tests/validators, schema/provenance/generation checks, exact diff inspection, current-source comparison, pinned primary evidence, and link/version/reference checks.

An evidence-backed no-change result is valid.

### 6. Recover

Absorb ordinary local disturbances while outcome, domain, authority, governing contract, and evidence boundary remain intact. Examples include validation failure, stale base, ordinary merge conflict, broken references, generated drift, task-local tool failure, and resolvable evidence gaps.

If repair requires a new normative, identity/policy, cross-S1, integration, security, licensing, or other undelegated decision, stop and escalate.

### 7. Preserve evidence

Preserve observable artifacts sufficient for another reviewer to reconstruct the run: domain, starting refs, governing contract, primary evidence, changed surfaces, validation, natural disturbances/recovery, human interventions, escalations, and final branch/commit/PR/issue/artifact refs.

Do not record hidden chain-of-thought.

### 8. Close or escalate

End with exactly one operational state:

- `CLOSED_CHANGE`;
- `CLOSED_NO_CHANGE`;
- `ESCALATED`;
- `NON_ADMITTED`.

## Human intervention

Human intervention is permitted but must be visible and attributed. Record which decision/right the human selected, constrained, overrode, stopped, or supplied with external information. Do not count that decision as agent-owned evidence.

If intervention changes the boundary, governing contract, delegated authority, or operational domain, re-establish admission before ordinary execution resumes.

Repeated human selection of ordinary decisive local decisions is evidence that those rights may actually remain human-owned.

## Returned S3 current control

A qualifying returned current-control decision may enter S1 only through the canonical [`../contracts/s3/current-control.md`](../contracts/s3/current-control.md) contract.

Do not treat arbitrary comments, labels, approvals, chat messages, scheduler state, or human instructions as S3 input. For a qualifying transaction:

1. acknowledge the transaction;
2. separate the returned current constraint from remaining S1 discretion;
3. apply the bounded instruction or explicitly reject/escalate;
4. re-establish admission if the instruction changes the S1 boundary/authority/contract;
5. preserve observable effect/closure evidence.

The constructor/transport does not become the S3 decision owner.

## Ownership boundary

The actor owns only the ordinary local decisions explicitly admitted for the run, except where recorded intervention or returned control assigns a specific decision elsewhere.

Unless separately delegated, ordinary S1 does not own:

- normative Profile semantics;
- system-wide Methodology authority;
- organizational identity, scope, or ultimate policy;
- cross-S1 coordination/current-control/audit/adaptation design;
- security/credential or licensing policy;
- protected/default-branch integration;
- permission expansion or administration.

A reviewable PR may therefore be a complete S1 outcome even when merge/integration remains separately owned.
