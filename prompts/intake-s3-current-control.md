# S3 — current-control intake for one real Organization choice

This is a **pre-admission operator prompt** for the existing [S3 constructor contract](../contracts/s3/current-control.md), [M1 trial #39](https://github.com/opensiro/vsm-oss-organization/issues/39), and [S3 role](../roles/S3.md). It is **not** an independent VSM definition, a new scheduler, a new autonomous controller, an assessment verdict, or a decision delegated by reading this file.

## Invocation

```text
S3: inspect current control
S3: consider <present Organization-wide choice / existing S1 work refs>
```

The first command inventories current operations **read-only**; the second inspects a specific proposed choice. Both can be used while the roadmap deliberately develops M1 before contributor overload. Merely typing a prefix, or the generic `continue` command, does not grant S3 authority or establish that a qualifying choice exists.

## Source-first intake

1. Bootstrap from [START_HERE](../START_HERE.md) to [ECOSYSTEM](../docs/ECOSYSTEM.md), the **current** Organization default branch, `TODO.md`, the exact owning issue and in-scope S1 repositories. Read the selected Profile and Methodology, [S1 decision envelopes](../contracts/s1/domain-contracts.md), and the existing S3 contract. Keep source refs and inspection time.
2. Identify **existing S1 work** at Index, Skills and/or Awesome with observable current commitments, relevant shared resources, live limits, dependencies, and actual operative status. An open issue is not automatically executing; a backlog slot is not a budget. Do not infer a crisis, scarcity, conflict, contributor availability or granted authority from repository metadata.
3. State a **specific present-tense decision** that only whole-system current regulation can legitimately close. Identify the relevant **whole-system current view**, affected S1 refs, concrete alternatives, potential effect on actual work, and the **S1 return target**. Test whether it instead belongs wholly to S1, S2, S4 or S5. Mere task assignment, documentation alignment, stale CI, or local PR review is insufficient.
4. Name the **legitimate decision owner** and cite the existing source of that right. Separate the actor's discretion from Github issues, prompts, validators, queues, schedulers, budget gates, or transport. Do not impersonate the parent, presume the operator is the owner, or interpret a generic `continue` as an owner's bounded S3 choice.
5. If a real qualifying choice and authority are established, prepare a compact **pre-decision packet**: system-in-focus; frozen real-work and contract refs; current view; S3 rationale; decision right and owner; actionable choices and their known consequences; allowed bounded response classes; S1 return target; observable closure criterion. Record the packet under the owning issue or a reviewable artifact. Only then open a `REQUESTED` transaction through the **existing** [transaction template](../control/s3-current-control-v1.template.json), with undecided fields explicitly pending until a genuine owner decision.
6. Have the legitimate owner make the **actual** bounded choice. If a concrete, authenticated decision was already provided for the frozen task boundary, preserve that evidence rather than asking again. Otherwise, surface only the specific owner decision that is needed; do not choose on their behalf. Once a genuine returned decision exists, use [`prompts/apply-s3-control.md`](apply-s3-control.md) to acknowledge/apply it in the affected S1, re-establish S1 admission if needed, and verify observable subsequent effects.
7. Close the transaction only on evidenced S1 return/effect or a justified explicit escalation/cancellation. Reassess function, decision ownership and closure separately under the selected Methodology, preserving the historical noncanonical [pre-assessment](../records/assessment-snapshots/2026-09-30-general-preassessment.md). The intake, packet, prompt, or a GitHub merge is **not evidence of `S3=C`**.

## Fail closed without invented evidence

If no substantive whole-Organization choice is identified, report **no S3 transaction** and the exact missing decision/right/current fact. Continue bounded source checks as useful, but do not make up a reviewer, scarcity, conflict, obligation, owner instruction, S3* finding, or returned S1 effect. In particular, a future contributor-growth benefit justifies constructing the capability on the roadmap; it does not constitute evidence that today's S3 function operated.
