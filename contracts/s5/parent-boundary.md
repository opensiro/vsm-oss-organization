# Parent-governed S5 boundary contract

This contract defines the first-party Organization path for composing a parent-governed S5 identity / ultimate-policy decision.

It applies the selected Profile and Methodology through [`../../UPSTREAM_CONTRACT.json`](../../UPSTREAM_CONTRACT.json). It does not redefine S5, parent mode `P`, recursion, or autonomy semantics. The existence of this contract does **not** establish `S5=P`; a real qualifying decision and returned closure are required.

## Purpose

Use this path only when the matter genuinely concerns identity, purpose, ultimate policy, legitimate authority, declared system boundary, or the delegation model of the bounded Opensiro VSM Harness OSS organization.

```text
ordinary Organization operation
        ↓
identity / ultimate-policy exception
        ↓ leaves delegated local envelope
legitimate parent authority
        ↓ authoritative decision
returned policy / identity decision
        ↓
Organization acknowledgement / application
        ↓
subsequent operation governed by returned decision
```

## Delegated local envelope

The following remain outside S5 when they can be closed under already-delegated lower-level authority:

- ordinary bounded Index, Skills, or Awesome S1 work;
- local implementation, validation, repair, reassessment, curation, and recovery;
- complementary S3* audit judgment over an admitted claim/risk;
- S3 current-control decisions inside an already-selected identity/policy envelope;
- ordinary repository maintenance, PR discussion, CI repair, scheduling, routing, merge mechanics, or use of an already-admitted external capability.

Human participation does not turn these matters into S5.

## Reserved S5 matters

Candidate S5 matters include changing the declared system-in-focus/repository participation boundary, purpose or viable-system identity, ultimate policy authority, delegated autonomy envelope, relation to normative semantic authority, consequential capability policy, or termination/merger/splitting/fundamental redefinition of the bounded organization.

Map the actual function first; these categories are not automatic labels.

## Legitimate parent

A positive parent-governed case requires a reconstructable legitimate parent role and concrete owner. Record:

1. parent role;
2. concrete actor or evidenced distributed arrangement;
3. primary evidence of legitimacy;
4. exact decisive right;
5. relevant limits.

Repository authorship, maintainer status, merge capability, administrator permissions, tool ownership, or possession of credentials are not sufficient by themselves.

The current declaration is [`parent-authority.md`](parent-authority.md).

## Escalation admission

Before using this path establish:

1. exact matter;
2. why it is identity/ultimate-policy rather than lower-level authority;
3. current delegated envelope and why it cannot close the matter;
4. decisive right;
5. legitimate parent;
6. primary evidence;
7. Organization return targets;
8. closure expectation.

If lower-level authority can safely close the matter, do not escalate it as S5.

## Decision record

Use [`../../templates/s5-parent-decision-record.md`](../../templates/s5-parent-decision-record.md). A material record should preserve system-in-focus, matter/rationale, lower-level authority considered, legitimate parent and evidence, decisive right, decision, returned constraint/policy/identity statement, support/enforcement separately, return targets, acknowledgement/application, observable effect, and closure refs.

## Return and closure

A parent decision closes S5 only when it returns into the Organization and governs later operation. The record should show the returned policy/identity constraint, affected Organization path, acknowledgement/application, and observable changed or intentionally preserved subsequent behavior.

## Support and enforcement boundary

Issues/PRs, branch rules, permissions, connectors, CI, labels, project fields, queues, schedulers, policy/config files, and deterministic checks may support, transport, or enforce a parent decision without owning S5.

Classify ownership from the decisive organizational judgment, not the strongest technical enforcement mechanism.
