## Granted subject: inside-and-now whole-system current control

The recipient may **choose**, but not pre-approve, one of the following only **for a separately source-admitted real present whole-system matter**, with legitimate actual authority beyond local S1/S2/S3* rights:

1. **Present operational commitment reconciliation:** a specific currently binding organizational commitment/constraint which an affected S1 cannot decide under its own contract.
2. **Current resource, priority or capacity regulation:** a documented actual shared resource/priority choice whose discretion genuinely belongs to the whole system. Ordinary `TODO.md` work ordering, milestone selection or task decomposition is **not sufficient**.
3. **Bounded current accountability and repair:** a named current whole-system constraint following an evidenced exception or S3* finding which local S1/S2/S3* authority cannot close; the S3* auditor does not become an S3 regulator.
4. **Current public-claim assurance:** only where the actual public assertion, present material obligation and whole-system right independently satisfy [the separately approved design envelope](../../docs/proposals/2026-10-14-s3-parent-assisted-general-mandate.md) and source-linked [PR #235 narrow test](https://github.com/opensiro/vsm-oss-organization/pull/235). **PR #235 remains non-operative and unmerged**; that design is supporting scope guidance, not an extra universal freeze authority.

**Effect may legitimately return to one S1** where the *nature of the right* is whole-system, not merely because multiple repositories are mentioned.

### Authorized response classes

- `CONTINUE` — an **actual considered** specific current whole-system matter, including intentionally preserved operation; never a rubber-stamped empty queue.
- `SET_CONSTRAINT` — a **proportionate, narrowly named** current operating limit with owner, specific obligation, measurable termination and S1 effect; does **not** rewrite Index/Skills/Awesome local facts or automatically block publications.
- `REQUIRE_REPAIR` — a bounded **current operational return** to a named S1 work item, with no takeover of that owner's independent technical/evidentiary adjudication.

**Never under this grant:** `STOP`, `SET_RETRY_BUDGET`, `OTHER_CURRENT_CONTROL`, Index grade override, all-batch freeze, forced reassessment, changing Profile/Methodology authority, S5 identity/boundary decisions, S3* audit judgments, independent reviewer identity or approval, blanket PR/CI gates, S1 curation/editorial choices, security/permissions policy, replacing existing source refs, automatic delegation onward, or silent reclassification of routine S1 work.

A separate attributable S5 grant is required before any expansion. Technical GitHub privileges are not substitutes.

## Mandatory human choice and agent-support protocol

1. **Read-only case preflight** by the agent: read live Organization `main`, this grant and S5 authorization; verify effective period/revocation; obtain selected Profile/Methodology, live Index/Skills/Awesome state, active existing S1 work and precise evidentiary scope. Check whether actual present whole-system regulation (not S1 repair, S2 coordination, S3* audit or S5 policy) is required.
2. **Owner packet BEFORE S3 choice:** present usually 2–3 materially distinct **source-pinned options**, including `NO_ACTION / preserve` or explicit `ESCALATE`, an agent recommendation **identified as advice**, costs/risks, affected S1 work, proposed allowed response class, limited exact instruction, rollback/expiry, follow-up and closure. No default selected by the agent.
3. **Human decisive act:** only the duly authorized `xLagerFeuer` acting as **S3 holder** may select a specific admitted present-case action. Attribute via a verifiable exact owner receipt. Same holder deciding an S3 case is **not** necessarily a new S5 policy event.
4. **After specific authorization**, instantiate [first-party S3 transaction](../../control/s3-current-control-v1.template.json) and [reviewable record](../../templates/s3-control-record.md) under [canonical S3 contract](current-control.md), with true `REQUESTED → DECIDED → APPLIED → CLOSED` or legitimate `ESCALATED/CANCELLED`. Never fabricate a prerequisite `REQUESTED` record or prefill a decision.
5. **Return to S1:** use [apply-s3-control](../../prompts/apply-s3-control.md) on an **existing affected S1 work item**. S1 checks its admission, **acknowledges/applies** the narrowly scoped decision or explicitly refuses/escalates for legitimate reasons, and records the actual subsequent outcome. Agent checks primary effect/provenance. A comment, CI pass, merge, transport or validator success is not S1 effect.
6. **Closure and return reporting:** preserve accepted/refused owner instruction, S1 return/effect references, expiry/revocation, whether S1 resumed/repaired/remained intentionally unchanged and a separate assessment note if requested. Owner may revoke or decline at any step; no independent approval is implied.

**Fail closed:** if actual context, decisive owner authority, selected case, consent, exact return ref or temporal window is missing, report `NO_S3_INTERVENTION / ESCALATED` and do not instruct S1. Agent option preparation may be carried out read-only without a case.
